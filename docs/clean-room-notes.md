# Clean-room 合规说明

本文档记录本项目的独立开发事实链，供版权合规审查使用。

## 设计来源

1. 本插件的**协议、数据模型、API 形态、代码结构、依赖选型均为从需求出发的独立设计**：
   - 信道安全采用 TLS-PSK（配对码仅存在于带外邀约 URI，经 HKDF 派生为 TLS 预共享密钥，永不明文过网）；
   - 设备身份采用无证书 Ed25519 密钥 + SPKI 指纹；
   - 数据模型为多设备注册表（单 vault 文件）；
   - API 为单端点 RPC 信封；
   - 运行时零第三方依赖。
2. 需求本身（"桌面出示一次性邀约 → 手机扫码 → 双向认证 → 设备入册 → 凭凭证重连"）是功能性需求，不来自任何特定实现的表达。

## 与宿主应用的接触范围

开发过程中分析过宿主应用（DeepSeek Harness）的插件加载机制，以及一个已安装的同类第三方插件的**公开 `.d.ts` 类型声明与文件清单**，目的仅限于确认宿主的加载契约。本仓库未复制、未改写、未参考该插件的任何实现代码、注释或文本。

使用的宿主集成事实（属功能性接口，非表达）：

- Cordis 插件入口导出 `name`（字符串）与 `apply(ctx, config?)`；
- 插件包经 profile 的 pnpm workspace 安装，通过 `package.json` 的 `dsh.profile.bundles` 声明加载，可用随包 `dsh.bundle.patch` 指向补丁文件完成树插入；
- web 客户端模块经全局模块加载器以 IIFE 包装注册。

## 机械防漂移

`tests/naming.test.mjs` 在每次测试时扫描全部源码、文档与配置，禁止出现对标产品名称及若干特征标识符（清单见该测试文件；本文件刻意不罗列，以免自身命中守卫）。守卫测试从项目第一天起即存在。
