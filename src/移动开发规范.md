# 移动开发规范（Vue 开发者视角）

> 配套文档：[开发环境启动教程.md](开发环境启动教程.md) · [RN-HarmonyOS-入门教程.md](RN-HarmonyOS-入门教程.md) · [项目目录架构设计.md](项目目录架构设计.md)
> 本文档是**写代码时应遵守的约定**，按"新写一个组件/接一个三方库/排查一个问题"的顺序组织。

---

## 1. 心智模型

- **没有浏览器、没有 DOM**。`div`→`View`，`img`→`Image`，`span/p/h1`→`Text`（带样式属性）。所有文本必须包在 `<Text>` 里，裸文字直接报错——RN 新手第一个编译错误。
- **RN 组件是原生控件的封装**，不是 DOM 节点；样式是 CSS 的子集，以 JS 对象表达。
- **单Activity/Ability + 单 WebView 心智**不适用：RN 是原生渲染，JS 只负责描述"现在界面长什么样"。
- **debug vs release**：debug 包 JS 运行时从 Metro 拉（需要 `hdc rport tcp:8098 tcp:8098`）；release 包 JS 打进安装包，不需要 Metro。类比 dev server vs 构建产物。

---

## 2. 概念对照表（Vue → RN）

| 你熟悉的（Vue） | RN 对应 | 差异要点 |
|---|---|---|
| SFC 三段式（template/script/style） | 函数组件 + JSX | 无模板，UI 即 JS 表达式；一个文件一个组件 |
| `createApp().mount()` | `AppRegistry.registerComponent` | 挂到原生容器 |
| Vite | Metro | dev server/解析/转译/HMR |
| `<style scoped>` | `StyleSheet.create` | 无级联/继承/伪类；flex 默认主轴 **column** |
| 组件库 | 内置 `View`/`Text`/`Image`/`ScrollView`/`FlatList` | 映射原生控件 |
| vue-router | `@react-navigation` | 三方库 |
| Pinia | Redux/Zustand/MobX | 生态分裂 |
| `ref()` / `watch()` | `useState()` / `useEffect()` | 依赖数组触发，时序语义不同 |
| `v-if` / `v-for` | JSX 三元 / `.map()` | |

## 3. 目录结构与 RNOH 接入规范

RN 官方不规定目录结构；本项目采用 **社区通用 RN 规范 + RNOH 特有规则** 的合并形态。
RNOH 对 JS 侧零额外约束，其规范集中在 harmony 壳侧与三方库接入流程。

### 3.1 目录树

```
src/（DSH Connector）
├── index.js / App.tsx / app.json      # RN CLI 固定入口（不动）
├── src/                               # 通用 RN 规范区
│   ├── screens/                       # 页面（XxxScreen.tsx；RN 通用词是 screens 不是 pages）
│   ├── components/                    # 公共组件（跨 ≥2 屏复用才进来），PascalCase 一文件一组件
│   ├── navigation/                    # React Navigation 配置
│   ├── hooks/                         # useXxx.ts，一个 hook 一个文件
│   ├── utils/                         # 公共纯函数（无 React 依赖）
│   ├── services/                      # API 请求层
│   ├── store/                         # 全局状态
│   ├── constants/  types/  theme/  assets/
│   └── specs/                         # RNOH 特有：自写原生模块的 codegen 规格（NativeXxx.ts）
│
└── harmony/                           # RNOH 壳工程（结构由模板固定）
    └── entry/
        ├── oh-package.json5           # 三方库 .har 挂载点
        ├── build-profile.json5        # abiFilters
        └── src/main/
            ├── module.json5           # 固定，不改
            ├── ets/
            │   ├── entryability/EntryAbility.ets  # 固定壳（继承 RNOH 基类）
            │   ├── pages/Index.ets              # 固定壳（挂 RNApp）
            │   ├── PackageProvider.ets          # 注册点：你的 RN 包（ArkTS 侧）
            │   ├── RNOHPackagesFactory.ets      # 包工厂清单
            │   ├── <YourPackage>/               # 自写原生模块的 ArkTS 实现（extends RNPackage）
            │   └── generated/                   # codegen 产物（禁改）
            └── cpp/
                ├── CMakeLists.txt               # 编排入口（含本项目 ffrt shim）
                ├── PackageProvider.cpp          # 注册点：你的 RN 包（C++ 侧）
                ├── autolinking.cmake            # 三方 har 自动链接（禁改）
                ├── generated/                   # codegen 产物（禁改）
                └── <YourPackage>/               # 自写模块的 C++ 部分（如有）
```

### 3.2 存放规则速查

| 内容 | 位置 | 规则 |
|---|---|---|
| 页面 | `src/screens/` | `XxxScreen.tsx`；本质是普通组件，被导航注册后才成为屏 |
| 公共组件 | `src/components/` | 跨 ≥2 屏复用才提升；屏私有组件放 `screens/<name>/components/` 就近 |
| 公共函数 | `src/utils/` | 纯函数、无 React 依赖；需要 state/effect 的是 hook 不是 util |
| hooks | `src/hooks/` | 强制 `useXxx` 命名 |
| 测试 | 与被测文件同目录 | `Button.tsx` ↔ `Button.test.tsx` |
| 静态资源 | `src/assets/` | `require('../assets/x.png')` 引入 |
| 平台分身 | 与本体同目录 | `Button.harmony.tsx` / `Button.android.tsx`，Metro 按平台就近解析 |

### 3.3 三条接入工作流（按"想做什么"选）

| 想做什么 | JS 侧 | harmony 侧 | 谁自动 |
|---|---|---|---|
| 用纯 JS 库 | `pnpm add` | 无 | — |
| 用带原生的三方库 | 装 `@react-native-oh-tpl/<库名>` | `oh-package.json5` 挂 `.har` + `ohpm install`（先关 Metro） | autolinking 自动注册双端，重建即可 |
| 自写原生能力 | `src/specs/NativeXxx.ts` 写 TurboModule 规格 | `ets/<YourPackage>/` 写实现 + 双侧 `PackageProvider` 注册 | codegen 自动生成桥接 |

**优先级铁律**：先查 RNOH 适配库（`@react-native-oh-tpl/*`），查无移植才自写——自写要同时维护 ArkTS + C++，成本高一个量级。

### 3.4 禁改清单

`harmony/entry/src/main/{cpp,ets}/{generated,codegen}/`、`autolinking.cmake`、各级 lock 文件（详见架构文档 §7）。

## 4. 组件编写规范

### 4.1 基本形态

```tsx
import { useState } from 'react';
import { StyleSheet, Text, View } from 'react-native';

interface GreetingProps {
  name: string;
}

export default function Greeting({ name }: GreetingProps) {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>你好，{name}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { padding: 16 },
  text: { fontSize: 16 },
});
```

### 4.2 铁律

1. **组件就是函数**；props 只读——改父级状态靠回调 props 往上传。
2. **任何文字必须包在 `<Text>` 里**（`<View>裸文本</View>` 直接报错）。
3. JSX 的 `{}` 内写任意 JS 表达式；条件渲染用 `&&`/三元，列表用 `.map()` 且**每项给稳定 `key`**（不要用数组下标当 key，除非列表纯静态）。
4. hooks 三戒条：
   - 依赖数组要诚实（漏写 = 闭包旧值 bug，多写 = 多余重渲染）；
   - 不要在条件/循环里调 hooks（调用顺序必须稳定）；
   - `useEffect` 是同步副作用的手段，不是生命周期钩子堆——能算出来的就别 effect。

### 4.3 状态管理

小规模用 `useState` 提升；跨组件共享优先选 **Zustand**（API 最接近组合式 store 的心智）。选型后全项目统一，不混用。

## 5. 样式规范

- 全部走 `StyleSheet.create`，**禁止内联对象字面量**（每次渲染新对象，破坏渲染复用）。
- 认清子集：没有选择器、没有级联、没有伪类；数值单位是 dp（密度无关像素）。
- 布局默认 flexbox 且 **主轴 column**（Web 默认 row）——90% 的"布局怎么竖着排"疑问源于此。
- 颜色/暗色模式：`useColorScheme()`；硬编码色值集中到一个 `theme.ts`，不散落。
- 安全区（刘海/圆角）：用 safe-area-context 的 `useSafeAreaInsets()`（注意需鸿蒙移植版，见 §7）。

---

## 6. 生命周期

- **组件级**：`useEffect(()=>{... return 清理函数}, [])` ≈ mounted/unmounted。
- **应用级**：前台/后台（鸿蒙侧 `RNAbility background/foreground`，hilog 可见）。JS 侧监听用 `AppState`（`react-native` 内置）。切后台暂停轮询/动画是移动端常规要求，Web 没有"后台"概念，这点必须习惯。
- 屏幕尺寸变化（旋转/折叠屏）：用 `useWindowDimensions()`，不要缓存宽高。

## 7. 三方库接入规范（本项目最容易踩的流程）

**决策树**：

```
这个库有原生代码吗？
├─ 纯 JS（如 lodash、dayjs、zustand）→ pnpm add 完事
└─ 带原生（凡涉及相机/存储/手势/安全区/导航…基本都有）
     → 必须查 RNOH 适配列表，装鸿蒙移植包，走完整流程 ↓
```

**带原生库的完整接入清单**（以 react-native-safe-area-context 为例）：

```bash
# 1) JS 侧：装 RNOH 移植包（版本需与 RN 0.84 兼容，查 RNOH 官方适配表）
pnpm add @react-native-oh-tpl/react-native-safe-area-context

# 2) 原生侧：harmony/entry/oh-package.json5 的 dependencies 加：
#    "@react-native-oh-tpl/react-native-safe-area-context":
#      "file:../node_modules/@react-native-oh-tpl/react-native-safe-area-context/harmony/react_native_safe_area_context.har"

# 3) 安装 ohpm 依赖（⚠️ 先关 Metro 和 DevEco Studio，防 EPERM）
cd harmony && ohpm install --all && cd ..

# 4) 重新构建安装 + 起 Metro（Git Bash 记得大写盘符同链，见开发环境启动教程 §0）
pnpm run harmony
```

- 只装了 npm 包没装移植包的典型症状：**白屏/调用即抛错**，Metro 日志出现
  `No harmony-specific third-party packages have been detected`。
- 移植包找不到时先查 [RNOH 文档的三方库适配列表](https://gitee.com/react-native-oh-library)。

## 8. 调试规范

| 场景 | 手段 |
|---|---|
| JS 逻辑/console | React Native DevTools（Metro 里按 `j`）或 Metro 控制台日志 |
| 界面不更新 | 先确认 Metro 活着、8098 转发在（`hdc rport`），再按 `r` reload |
| Metro 报解析错误 | 优先怀疑 metro.config.js / 平台分身文件，改后必须**杀干净所有 node 重启 Metro** |
| 白屏但应用存活 | 看教程 §6.7 决策树（多数是三方库移植缺失） |
| 应用秒退 | faultlogger 崩溃文件：`hdc shell "cat $(ls -t /data/log/faultlog/faultlogger/jscrash-* | head -1)"` |
| 原生构建失败 | `tail rn-harmony-build.log` + 教程 §9 决策树 |
| RNOH 运行日志 | `hdc shell "hilog -x \| grep -iE 'rnoh\|ReactNativeJS'"` |

## 9. 发布注意

- **ABI**：真机 arm64-v8a，模拟器 x86_64；`abiFilters` 双配（本项目已配），发版前确认产物包含目标 ABI。
- **签名**：模拟器可装未签名包；真机/上架必须配置 `signingConfigs`。
- **包名**：`AppScope/app.json5` 的 bundleName 是应用唯一 ID，确定后不要改（数据/升级都挂在它上面）。
- **release 包**：JS 打进 HAP，体积变大、启动不再依赖 Metro；发版前用 release 模式过一遍主要流程（debug 的行为差异会暴露依赖问题）。

## 10. 常见禁忌速记

- 长列表用 `.map()` 渲染几百项 → 用 `FlatList`/`SectionList`。
- 内联箭头函数/对象字面量传给深层组件 → 高频重渲染场景先 memo。
- `console.log` 遍地 → 打包前清理或接日志开关（debug 与 release 行为不同）。
- 图片只给本地大图 → 该走网络/压缩资源的走资源管线。
- 在 render 里直接改 state/props → React 单向数据流，改状态永远走 setState。
