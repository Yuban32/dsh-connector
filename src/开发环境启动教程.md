# 开发环境启动教程（HarmonyOS 手机端）

> 目标：把「DevEco 模拟器 + 应用 + Metro 热更新」这条调试链跑起来。
> 本文只给**照着做就能跑**的最短路径；原理与踩坑细节一律指向
> [RN-HarmonyOS-入门教程.md](RN-HarmonyOS-入门教程.md)（下称"教程"）。
>
> **项目根 = 仓库的 `src/` 目录**，下文命令默认在此执行。
> 应用包名 `com.yuban32.dshconnector`，入口 Ability `EntryAbility`。

---

## 0. 两条环境规则（先记住，后文全是它们的应用）

| 规则 | 内容 | 原因 |
|---|---|---|
| **端口 8098** | Metro 与构建一律用 8098（已内置在 package.json scripts，不要手改端口） | 8081/8082 常被 WinNAT 动态排除段吞掉：绑定即 `EACCES`，表现为 Metro"闪退"；排除段随系统重启漂移。教程 §6.8。**hdc 默认服务端口 8710 也属同类受害者**（2026-11-18 已用"缩小动态端口范围"持久修复，见 §6.17） |
| **大写盘符** | Git Bash 里跑构建：`cd` 必须写**大写** `J:/...`，且与构建命令**同一条命令链** | hvigor 对 cwd 做大小写敏感的字符串全等校验，小写盘符必报 `00303149 Path not found`——路径明明存在，报错路径是幌子。教程 §6.13 |

> 最省心的分工：**构建命令放 PowerShell / CMD / DevEco 终端**跑（天然大写盘符），
> Git Bash 用来跑 `pnpm start`、`hdc`、`ohpm` 等非构建命令。

## 2. 首次初始化（新 clone / 依赖目录被清空后）

> ⚠️ 步骤 0–2 期间**必须关闭 Metro 和 DevEco Studio**：它们的文件监视器会与
> ohpm 抢 `oh_modules` 的文件句柄，Windows 上表现为 `EPERM ... rename`（教程 §6.1）。

```bash
# 0) 关闭 Metro（node 进程）与 DevEco Studio

# 1) 安装 JS 依赖（在 src/ 下）
pnpm install

# 2) 安装鸿蒙侧依赖
cd harmony && ohpm install --all && cd ..
```

3) 打开 DevEco Studio → Device Manager → 创建/启动模拟器（**x86_64** 镜像）。
4) 核对设备在线：

```bash
hdc list targets        # 期望输出包含 127.0.0.1:5555
```

## 3. 每日启动流程

建议开两个终端：**终端 A 只跑 Metro**，**终端 B 跑其余命令**。

```text
终端 A: pnpm start ──┐
                     ▼
终端 B: 模拟器 → 等 hdc 可见 → 端口转发 → （需要时）构建安装 → 启动应用 → 验证
```

> ⚠️ **模拟器开机 ≠ hdc 可见**：模拟器窗口弹出后，还要 1~3 分钟才会在
> `hdc list targets` 里出现（期间输出为空）。**这条命令有输出之前，不要跑
> 任何 `hdc` 命令，更不要跑 `pnpm run harmony`**——原因见 §3③ 的"双模拟器"陷阱。

### ① 起 Metro（终端 A）

```bash
pnpm start    # 端口 8098 已内置；看到 Metro 监听 8098 即成功
```

### ② 启动模拟器 + 端口转发（终端 B）

DevEco Device Manager 启动模拟器。**模拟器每次冷启动后**都要重做反向端口转发
（让模拟器内的 `localhost:8098` 指回主机的 Metro）：

```bash
hdc fport rm tcp:8098 tcp:8098   # 清旧规则（没有会报 rule is not exist，忽略即可；3.2.0f 没有 `rport rm` 子命令）
hdc rport tcp:8098 tcp:8098      # 期望输出 Forwardport result:OK
hdc fport ls                     # 期望输出含 127.0.0.1:5555 tcp:8098 tcp:8098 [Reverse] —— 务必亲眼确认
```

> ⚠️ **列/删规则都用 `fport`**（hdc 3.2.0f 没有 `rport ls` / `rport rm` 子命令，
> 会报 Incorrect forward command；`fport ls` 同时列出正向与反向规则）。
>
> ⚠️ **`rport` 报 `TCP Port listen failed at 8098`**：模拟器**内部**有个孤儿 hdcd
> 监听占着 8098——host 侧规则已消失（hdc 服务端重启/被 kill 过）而设备端监听未
> 释放，且 `fport rm` 删不掉（rule is not exist）、shell 权限杀不了 hdcd。
> **唯一解法：重启模拟器**（关掉窗口重开，等注册后重做本步）。
> 预防：别在模拟器开着时 kill hdc 服务端；先 `fport rm` 清规则再动服务端。
>
> ⚠️ **转发建不上 / hdc 命令零输出**，两种最常见原因：
> ① 命令在模拟器 hdc 注册完成前执行（§3 开头的警告）；② **hdc 服务端起不来**
> ——8710 被系统端口排除段吞掉，所有 hdc 命令静默失败（exit 0、无输出），
> 表现为模拟器在 Device Manager 里明明在跑、`hdc list targets` 却是空的。
> 诊断与修复见教程 §6.17。③ `hdc list targets` 列出了**两台**设备——不带
> `-t` 的命令此时会报错退出。两台模拟器是异常状态，全部关掉只留一台（§3③ 陷阱）。

### ③ 启动应用（终端 B）

**日常 JS 开发（应用已装过）**——跳过构建，直接启动：

```bash
hdc shell aa start -a EntryAbility -b com.yuban32.dshconnector
```

**首次安装 / 原生侧有改动**（依赖、CMake、build-profile、.har）——走一次构建安装
（首次约 2~6 分钟；Git Bash 下注意大写盘符同链）：

```bash
cd "J:/Development/HarmonyOS/ds-connector/src" && pnpm run harmony
```

`pnpm run harmony` = `react-native run-harmony --port 8098 --no-packager`：
构建 → hdc 安装 → 自动启动应用。`--no-packager` 表示 Metro 由步骤 ① 自己管，
不让 run-harmony 另开窗口拉起第二个 Metro 抢文件（教程 §6.8 附带坑 2）。

两点**设计行为**，不是故障：

- **跑完 `[3/3] installing and opening app finished` 后命令直接退出**：run-harmony
  是一次性命令，退出即成功，模拟器与应用应当**继续运行**。
- **它自带 rport**：装完会自己执行 `hdc -t <设备> rport tcp:8098 tcp:8098`
  （紧跟在 `aa start` 之后，竞速窗口极小），所以构建安装路径之后一般不用手动补转发。

> ⚠️ **"双模拟器"陷阱**：`run-harmony` 发现 `hdc list targets` 里没有 `Connected`
> 设备时，会**自动拉起一台模拟器**——永远取 `Emulator.exe --list` 输出的第一台
> （本机 = Mate 80 RS），并盲目指定 `127.0.0.1:5555`。如果你手头的模拟器还在
> 开机窗口期（hdc 里看不到它），它就会再开一台，于是出现两个模拟器窗口。
> 两个模拟器在线时，教程里所有不带 `-t` 的 `hdc` 命令（rport、aa start…）
> 都会报错失效，应用可能装进你没在看的那台。
>
> **中招后处理**：两台全部关掉 → 回到 §3② 只启动一台 → 等待注册 → 重跑命令。
> 多台在线时只想精确指定目标，可给构建命令加 `--simulator 127.0.0.1:5555`。

### ④ 验证清单

| 检查点 | 手段/现象 |
|---|---|
| 模拟器在线 | `hdc list targets` |
| 应用进程活着 | `hdc shell "pidof com.yuban32.dshconnector"` 有输出 |

## 4. 日常开发循环

- 改 JS/TS → 保存即热更新；不生效时：Metro 终端按 `r` 全量 reload，或重启应用
- 只有 JS 改动 → 永远不需要重新构建，Metro 拉的 bundle 已是新代码
- 原生/依赖改动 → 关 Metro → 走 §5 流程 → 重建 → 重启 Metro

## 5. 改动依赖后的完整流程（最易翻车的序列）

```bash
# 0) 关 Metro（和 DevEco）！
# 1) JS 侧装包——版本纪律见教程 §6.9/§6.14（RNOH core/CLI 与移植版一律精确钉死，禁 ^）
pnpm add <包名>@<精确版本>

# 2) 带原生的三方库：还要在 harmony/oh-package.json5 挂 .har
#    流程细节：教程 §6.10 / §6.14、移动开发规范.md §7

# 3) 安装 ohpm 依赖（Metro 已关）
cd harmony && ohpm install --all && cd ..

# 4) 重建安装（Git Bash 大写盘符同链）
cd "J:/Development/HarmonyOS/ds-connector/src" && pnpm run harmony

# 5) 重启 Metro；动过 node_modules 必须清缓存（教程 §6.11）
pnpm start -- --reset-cache
```

## 6. 停止与重置

| 动作 | 命令 |
|---|---|
| 停 Metro | 终端 A `Ctrl+C`；要清干净所有实例：`taskkill //F //IM node.exe`（Git Bash 里斜杠要双写） |
| 停应用 | `hdc shell aa force-stop com.yuban32.dshconnector` |
| 清构建缓存 | 删 `harmony/entry/.cxx/`（重配约 +25s）、`harmony/entry/build/`——目录说明见[项目目录架构设计.md](项目目录架构设计.md) §5 |
| 重置依赖 | 关 Metro/DevEco → 删 `harmony/oh_modules/` → 回到 §2 重装 |

## 7. 启动失败速查

| 症状 | 先查 | 详见教程 |
|---|---|---|
| Metro 起不来 / 窗口闪退 | `netsh interface ipv4 show excludedportrange protocol=tcp` 是否吞了 8098；残留 node 占口 | §6.8 |
| **hdc 命令零输出 / 模拟器明明在跑却看不见** | `hdc -l5 list targets` 找 bind 报错；排除段是否吞 8710（hdc 服务端口）；修法见专修 | §6.17 |
| **`rport` 报 `TCP Port listen failed at 8098`** | 模拟器内有孤儿 hdcd 监听；重启模拟器（细节含诊断命令） | §6.18 |
| 构建秒败 `00303149 Path not found` | cwd 盘符大小写：`node -e "console.log(process.cwd())"` | §6.13 |
| 构建报 `Filename longer than 260 characters` | ninja 版本（须 1.13.x） | §6.2 |
| 升级 DevEco 后 ninja 报 `undefined` | 旧 `.cxx` 缓存钉死已消失的编译器路径：删 `harmony/entry/.cxx/` 重建 | §6.15 |
| 应用启动即崩（秒退） | 读崩溃文件：`hdc shell "cat $(ls -t /data/log/faultlog/faultlogger/jscrash-* \| head -1) \| head -60"`；见 `libRNOHApp is undefined` = ABI 不匹配 | §6.3 |
| 白屏但应用存活 | Metro 是否有请求进来；日志出现 `No harmony-specific third-party packages...` = 移植库缺失 | §6.7、§9 |
| 改代码不生效 | Metro 活着？§3② 的 rport 做了没？按 `r` reload 试过没？ | §3 |
| Metro 报 `No apps connected` | 见下方专修流程 | §3②③ |
| 新装库后构建报 `Cannot find module '@react-native-ohos/...'` | 先手动 `ohpm install --all` 再构建 | §6.10 |

完整故障决策树：教程 §9。

### `No apps connected` 专修（按序执行，多数在第 3 步痊愈）

含义：模拟器里的应用**从未与 Metro 建立 WebSocket**——debug 包的 rawfile 里没有
兜底 bundle，启动时连不上 Metro 就是白屏且不再自愈，按 `r` 无效。逐项排查：

```bash
hdc list targets                     # ① 只许一行输出；空 = hdc 死了（§6.17）或模拟器没注册；两行 = 双模拟器陷阱
hdc shell "pidof com.yuban32.dshconnector"   # ② 有输出=应用活着；无输出=没装或崩了，查 §7 秒退行
hdc fport ls                         # ③ 必须含 ... tcp:8098 tcp:8098 [Reverse]；没有→重做 §3②
```

前三步都正常却仍连不上（典型于应用抢在 rport 之前发起了首次 bundle 请求）：
**重启应用即可**——转发已就位，这次启动就能拉到 bundle：

```bash
hdc shell aa force-stop com.yuban32.dshconnector
hdc shell aa start -a EntryAbility -b com.yuban32.dshconnector
```

验证：Metro 终端出现 bundle 请求日志（首次打包 2~5 分钟，§3④）。

## 8. 常用命令速查

```bash
# —— 环境状态 ——
hdc list targets                                          # 设备在线

# —— 每日 ——

hdc list targets                                          # 模拟器开机后先等这行有输出！
hdc rport rm tcp:8098 tcp:8098 ; hdc rport tcp:8098 tcp:8098   # 模拟器冷启动后
```
